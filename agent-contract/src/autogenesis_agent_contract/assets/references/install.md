# Machine bootstrap and Coding Agent activation

Use only for installing, activating, repairing, or diagnosing AutoGenesis itself. Do not select a target platform, inspect devices or applications, install Appium dependencies, or create an automation session.

## Resolve the route

Establish the native host, absolute business project, Coding Agent (`omp`, `pi`, `codex`, or `copilot`), selected Python/isolation policy, safely disclosed package-source host and config-source class, and `user` or `project` Skill scope. Infer a unique answer from conversation and safe evidence. Ask once only when materially different clients or scopes remain; never ask the user to choose internal package or configuration mechanics.

Classify the request as `install` when packages or Skill are absent, `activate` when valid artifacts lack an active client MCP entry, `repair` when observed package/Skill/scope/configuration/identity drift prevents use, or `diagnose` when only read-only fault isolation is authorized. An explicit install, activate, or repair request authorizes its complete unchanged plan after disclosure. “Installed but unavailable” authorizes diagnosis, not configuration writes.

## Observe only bootstrap facts

Inspect the selected installed Python environment and first-party package versions, CLI entrypoint, canonical Skill in the selected discovery scope, conflicting user/project or legacy Skills, and the selected Agent's active MCP command/argv/cwd entry. Preserve every unrelated MCP entry byte-equivalently. Do not expand a solved launcher/configuration fault into target, SDK, Driver, device, application, or whole-environment discovery.

Before the CLI exists, follow the immutable Agent Install Prompt. Candidate trust requires the canonical repository, exact positive Actions run and run attempt, head commit, attempt-qualified artifact name, and exactly one unexpired immutable artifact with a positive observed artifact ID; resolve and download by that ID before interpreting bundle instructions. Public trust requires the exact immutable GitHub Release ID, tag, commit, and asset identities. Only then rely on complete `SHA256SUMS`; checksums cover every final asset including the prompt and exclude only themselves, but never replace the external anchor. The prompt path selects a verified local private per-user parent, generates one exact disposable transaction path with at least 128 bits of cryptographic randomness, includes that exact path in the immutable plan, and obtains explicit approval before reservation. Its environment, staging, download, extraction, and cache children are dedicated to the exact Candidate or public Release. It never uses or modifies ambient or pre-existing state.

## Apply one canonical plan

Use the package manager only for the authenticated wheel set and `autogenesis install` as the sole Skill installer:

```text
autogenesis install --scope <user|project> --project-root <absolute-project> --json
```

Disclose packages and exact authenticated artifact identities; the verified private parent identity, current-user ownership, permissions/ACLs, and local filesystem; the cryptographic randomness requirement and exact new absolute disposable transaction root with its environment, staging, download, extraction, and cache children; selected base Python; validated package-source host and config-source class; package policy; Skill scope/destination; MCP configuration destination and exact entry; every write/process; persistence; consequences; rollback; and verification once. Reject shared, untrusted, unsafe, or network-backed parents, other-identity write/create/delete/delete-child control, and every symlink/reparse component. Require the exact leaf and children to be absent and obtain explicit approval for that exact path before reservation or any other change.

After approval, re-open and verify the private parent without following links and atomically create the exact approved leaf with fail-if-exists and no-follow semantics. A collision, changed parent or leaf, symlink, reparse point, unsafe permission, or unverifiable native identity stops and requires a newly generated random path, fresh immutable plan, and fresh approval; never reuse or repurpose the path. Acquire one exclusive transaction lock for the complete create/install/verify/rollback/cleanup lifecycle and reject a concurrent installer. Record stable parent and leaf identities plus a private unpredictable ownership marker. Before and after every reservation, venv, staging, download, extraction, install, Skill, MCP, verification, acceptance, rollback, and cleanup phase, recheck the lock, parent identity/ownership/permissions, exact leaf identity, and marker; any mismatch stops before another mutation. Use no-follow native opens for reservation and cleanup where supported, and platform-native atomic no-replace final placement. Standard pathname-based stdlib `venv`, `pip`, and installed AutoGenesis, Runtime, or CLI child operations are permitted within the exact transaction root after successful reservation. The boundary trusts processes already running as the same OS user identity and does not claim to prevent malicious same-user replacement of pathname-addressed state; do not propose a privileged or sandboxed native Bootstrap. Create the venv with the selected base Python in isolated mode (`-I`, `-E`, `-s`, plus `-S` where compatible with stdlib `venv`). Launch every child with an explicit minimal environment. Omit by name without reading values all `PYTHON*` variables and Python startup customization, including `PYTHONPATH` and `sitecustomize`. Remove all ambient `PIP_*` and `UV_*` variables by name without reading values. For pip, set only `PIP_CONFIG_FILE` to the platform null file (`/dev/null` on macOS, `NUL` on Windows), stop if null-config isolation cannot be established, and invoke every pip operation with `--isolated`. Before staging, bind pip acquisition to the transaction's `--dest` download root and `--cache-dir` cache root, authenticated requirements and hashes, and the approved opaque source/auth interface. Install from staging through the disposable Python with `-I -E -s -m pip --isolated --disable-pip-version-check install --no-input --no-index --no-cache-dir --find-links <transaction-stage> --require-hashes --no-deps -r <transaction-requirements>` into the reserved venv. If authenticated uv is used, invoke it with `--no-config`; bind its cache, download, staging, destination, Python, and source options to approved transaction roots and the opaque interface; then use explicit `--no-index --no-cache --find-links <transaction-stage> --require-hashes --no-deps` after staging. Never use ambient user/global package-manager configuration, cache, source, target, prefix, credentials, or an ambient uv executable. After staging every package operation is offline and no-index. Use only the disposable environment's absolute Python and entrypoints while the phase-boundary checks continue to pass. Linux and WSL stop before mutation.

Before echo or use, validate source host as exactly a canonical lowercase ASCII DNS hostname, canonical IPv4 literal, or bracketed canonical IPv6 literal with no scheme, port, userinfo, path, percent escape, whitespace, control, query, or fragment. Validate config-source class against exactly `managed-policy`, `user-approved`, `default-public`, or `undisclosed`. The opaque interface's trust must be established independently; self-attestation is insufficient. Invalid metadata is never echoed, becomes `undisclosed`, and stops installation. Never inspect, parse, print, log, serialize, echo, or derive metadata from full index URLs, URL userinfo, credentials, percent-encoded credentials, tokens, queries, fragments, authorization data, credential-bearing environment values, raw pip/uv configuration, errors, command output, or evidence payloads. Redaction after reading is not a safety boundary. Do not dump package-manager configuration or environment variables.

Treat the installer result as evidence only for layers it reports. Do not rerun an identical install for reassurance; reuse `unchanged`. On a stable error inspect only its failing layer instead of discovering flags through repeated mutations. Configure or repair the selected Agent through its native MCP mechanism with the disposable environment's absolute Runtime command and argv plus explicit minimal child environment, never a shell-interpolated launch string. Retain all existing configuration. Recheck the exclusive lock, private parent, exact leaf identity, permissions, and marker before and after the configuration phase.

On installation or verification failure, cancellation, denial, identity/digest mismatch, supersession, or rollback, stop dependent prompt-owned processes. Before cleanup and before deleting each root, recheck the exclusive transaction lock, verified private parent identity/ownership/permissions, exact leaf identity, and private ownership marker. Open reservation and cleanup targets with no-follow semantics where supported and delete only exact prompt-created roots whose current identities and markers still match the approved transaction. A missing lock, changed permission, substituted identity, marker mismatch, symlink, reparse point, or ambiguity forbids entering or deleting that state; preserve it for investigation. Remove prompt-created selected-scope Skill/MCP state only when its captured identity still matches. Never delete or repurpose a pre-existing or mismatched object, restore a cached Skill/Runtime schema or write-capable generated-code inventory, or alter unrelated environments, files, configuration, or credentials. Reload the Agent and prove the exact removed or newly accepted inventory before use.

## Prove Machine Ready

Reload through the current Agent when available, then prove through that Agent: the canonical Skill resolves to the approved scope and exact bytes with no shadow/legacy copy; the Runtime completes MCP initialize; required prompts/tools/resources are discoverable; and `autogenesis://agent-contract/identity` matches the installed Contract requirement.

A package command, `--version`, destination file, standalone SDK client, or config write alone is not Machine Ready. If automatic reload is unavailable, stop at configured/reload-required with exactly that user action and preserve the original request in resume context. Never create an application session to prove installation.

Return Outcome, project/client/scope, observed and selected installation, drift classification, changes/approval, actual Agent discovery evidence, one Required action if any, and Resume context. Keep raw paths and diagnostics out of durable evidence.
